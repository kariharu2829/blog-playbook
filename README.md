# ブログ運営の型（汎用版）

どんなジャンル・どんな案件でも同じ手順で回すための運営手順書。
特定サイトの固有事情はここに書かない（各サイトのリポジトリに書く）。

## ブログは1本の数式を回す事業

```
月収益 = 検索流入数 × 記事→案件ページ遷移率 × 成約率 × 1件あたり報酬
```

すべての工程は、この4つのどれかを上げるためにある。
**左側（案件と単価）を先に決めてから、右側（記事）を作る。** この順番を崩すと後で全部書き直しになる。

ブログは「営業代行」という事業。創業計画書の「取扱商品・客単価・売上」が埋まらないブログは、ゴールのないマラソンになる。
現役で稼いでいる3人のブロガーの流れは全員同じで、**売る商品を決める → その商品を売るKWを選ぶ → 上位を取れる構成を作る → 書いて出す → 分析して直す**。この骨格をそのまま採用する。

状態は「未着手 → 検討中 → 確定」の3段階。確定したステップだけを実運用で使う。
**第1版（2026-09-11）：ステップ0〜6すべて確定。** 以後は実運用で合わなかった箇所を直して育てる。

## 使い方（新しいサイトを始めるとき）

1. サイト用のリポジトリを作り、`prompts/トンマナMD_雛形.md` と `_template/ブログ創業計画書.xlsx` をコピーして置く
2. ブログ創業計画書を、ステップ0 → 1 → 2 の順に埋める（合計で1か月かけてよい）。埋まるまでブログを開設しない
3. 記事一覧の最初の成約記事から、ステップ3 → 4 を回す
4. 公開4週間後からステップ5を月次で回す
5. 月5万円を3か月連続で超えたらステップ6を開く

### 使い方（すでに記事があるサイトに当てはめるとき）

順番は同じだが、**1と2のあいだに「いまあるものの転記」が入る**。

1. サイトのリポジトリに `_template/ブログ創業計画書.xlsx` をコピーする
2. **いまあるものを先に転記する** — 公開済み記事を「記事一覧」に（公開日・URL・GSCの順位／表示／クリックまで）、提携済み・調査済みの案件を「案件評価表」に。**ここで「必要記事数に足りない本数」より先に「いまの記事が換金できる状態か」が見える**
3. ステップ0を埋める。「開始時点の既存記事数」に公開済み本数を入れ、週あたり公開本数は**実績**で出す（例: 直近20週で7本＝0.35本/週）。創業計画書 ９ の「創業当初」列は仮置きではなく実測を入れる
4. ステップ1・2は新規サイトと同じ。ただし「売る場所を決める」は既に答えが出ていることが多い（[steps/01](steps/01_売る商品を決める.md) の4象限）
5. 以降は同じ

既存サイトでよく出る結論は「記事が足りない」ではなく **「クリックは来ているのに踏む先が無い」**。その場合は新規執筆より提携とリンク設置が先。

### 土台：ここで収益の9割が決まる（1か月かけてよい）
0. **ゴール設定**：目標月収・期限・投下時間・体験資産を棚卸しし、ラッコM&Aの実データで必要記事数と必要単価を逆算する
1. **売る商品を決める**：ASPを1週間かけて全件見て、成果報酬 ＞ 成果条件 ＞ EPC ＞ 確定率 の順で主力1件・サブ2件までを決める
2. **キーワード選定**：商品を売るKWを1週間かけて洗い出し、Google検索で「1ページ目に個人ブログがあるか」「DAは低いか」を自分の目で確かめ、グループ化して優先順位と記事一覧を作る。**ここが終わるまでブログを開設しない**

土台3ステップの成果物は **「ブログ創業計画書」1枚**に集約する（取扱商品と客単価／目標売上と必要PV・必要記事数／狙うKW一覧と導線／週あたり公開本数と12か月マイルストーン）。
雛形は [_template/ブログ創業計画書.xlsx](_template/ブログ創業計画書.xlsx)（日本政策金融公庫の創業計画書10項目をブログ用に写したもの。対応表は [references/創業計画書_公庫様式の項目メモ.md](references/創業計画書_公庫様式の項目メモ.md)）。サイトごとにコピーして使う。

### 記事ごと：1本ずつ繰り返す
3. **タイトル・目次構成**：本人が先に仮説を書き、AIのリサーチシートで答え合わせし、本人が確定する。3ルール＝重要なH2から順に／H3はH2の答え／余計なH2を書かない。AIに丸投げしない
4. **執筆・公開**：AIが初稿、本人がリード文・体験・セールスを書き、本文を直す。FAQは実際の質問から。公開前チェックを通し、本人が公開する。最後に差分学習でトンマナMDを育てる。完璧は求めない
5. **分析・改善**：公開4週間後に初めて順位を見る。毎月1日に全記事の順位・CTR・遷移・成約を一覧にし、分岐表で「詰まっている場所」を判定して月3〜5本をリライトする。10〜20位が本命。3か月ごとに案件と逆算の変数を見直す

### 超えてから
6. **拡張・仕組み化**：確定報酬で月5万円を3か月連続、かつステップ5が回っていることが着手条件。打ち手は特単交渉 → 外注化 → 横展開 → SNS・メルマガの順で検討。中身は着手時に実績を見て埋める

## 数値の目安（3人の実践者のばらつきを優先順位で吸収）

| 項目 | こーにゃん氏 | やましょ氏 | ぴーたん氏 | 手順書での扱い |
|---|---|---|---|---|
| 成果報酬の下限 | 3,000円、好ましくは5,000円 | 3,000円 | 2,000円 | 2,000円未満は見ない。3,000円以上を候補、5,000円以上を優先 |
| 承認率・確定率 | 60%、好ましくは80% | 50% | 記載なし | 50%未満は落とす。60%以上を候補、80%以上を優先 |
| 検索ボリューム | 100以上を優先 | 10以上 | 10〜100の3語KW | 10未満は書かない。10〜100を初期の主戦場、100以上を優先 |
| 個人ブログの存在 | 1ページ目に1つでもあれば狙う | 1ページ目に個人サイトがある | 記載なし | 必須条件 |
| DA | 20未満、好ましくは1桁 | 記載なし | 記載なし | 20未満を候補、10未満を優先 |

## 手順書は2階建て

- `steps/`：人が読む手順書。目的・インプット・やること・アウトプット・完了基準・よくある失敗
- `prompts/`：その手順のうちAIに任せる部分を、そのまま読ませるファイル（[prompts/README.md](prompts/README.md)）。記事ごとの層は毎回回すので、人が指示を打ち直さずに済むよう仕組み化する。トンマナMDのようにサイトごとに育つものは雛形だけ置き、実体は各サイトのリポジトリに持つ

各ステップに散っている定期作業を1枚にまとめたもの。迷ったらここを見る。

| いつ | やること | 誰が | 出どころ |
|---|---|---|---|
| 記事を公開した日 | GSCのURL検査でインデックス登録をリクエスト／記事ログに公開日・代表KW・URLを記録／差分学習を実行し初稿生存率を記録 | 本人／AI | ステップ4・5 |
| 公開1〜2週間後 | 【Level2予定】の体験追記（実測データ・使用感） | 本人 | ステップ5 |
| 公開4週間後 | GSCで初めて順位を見る（狙ったKWで表示されているか、何位か）。一喜一憂しない | 本人 | ステップ5 |
| 毎週1回 | ASPの新着プログラムを見る（新着順・カテゴリ問わず）。良い案件は4象限で判断し、動かないなら「お気に入り」に寝かせる | 本人（通知はAI可） | ステップ1 |
| 毎週 | 記事一覧の優先順位どおりに、ステップ3 → 4 を回す（週あたり公開本数は創業計画書の４のとおり） | 本人＋AI | ステップ3・4 |
| 毎月1日 | 記事一覧の数字を更新（順位・表示・クリック・CTR・遷移・発生・確定）／全記事に「詰まっている場所」と「次の打ち手」を1行ずつ／今月のリライト対象を3〜5本に絞る | AI（転記）／本人（判定） | ステップ5 |
| 毎月 | 絞った3〜5本をリライトし、リライト日と変更点を記録 | 本人＋AI | ステップ5 |
| 3か月ごと | 案件別の確定率を見直し、目安（60%）を下回り続ける案件はサブへ降格を検討／集客記事 → 成約記事の流れを確認し内部リンクを直す／創業計画書の見通し（９）を実測で更新し、仮置き値を差し替える | 本人 | ステップ5・0 |
| 月5万円を3か月連続で超えたら | ステップ6の着手条件を確認し、特単交渉 → 外注化 → 横展開 → SNS の順で検討 | 本人 | ステップ6 |
| 手順どおりに動かなかったとき | その場でこのリポジトリの該当ステップを直す | 本人＋AI | 育て方 |

## この手順書の範囲外（明記しておくこと）

- **SNS集客**は範囲外。この手順書は検索流入（SEO）で成約記事に流す前提で書いている。SNSはステップ6で検索が安定してから
- **ブログ開設の手順**（ドメイン・サーバー・WordPress・テーマ・GSCとGA4の接続・運営者情報やプライバシーポリシーなどの固定ページ）は未収録。ステップ2の完了後、開設時に別途用意する
- **ジャンル別の法令**（美容・健康は薬機法、金融は金商法・貸金業法、医療はYMYLの断定禁止など）は、トンマナMDの一般則（景表法・断定禁止）しか入っていない。ジャンルを決めたら、そのジャンルの法令チェック項目を各サイトのトンマナMDに足す。案件評価表の「NG表現・承認条件」列に広告主の掲載条件を写すこと

## 1ステップの型

各ステップは必ず同じ6項目で書く（雛形: [_template/ステップの型.md](_template/ステップの型.md)）。

- **目的**：このステップで何が決まれば次に進めるか
- **インプット**：前のステップから受け取るもの
- **やること**：手順を番号で
- **アウトプット**：成果物のファイル名と形式
- **完了基準**：数値か Yes/No で判定できる条件
- **よくある失敗**：典型的な脱線パターン

## 役割分担の原則（全ステップ共通）

| 本人がやる（AIに任せない） | AIやツールに任せてよい |
|---|---|
| ASPの全件閲覧と、自分の経験との照らし合わせ | お気に入りの一覧化、評価表への転記、新着通知 |
| 検索結果を見て「1ページ目に入れるか」を判断する | KWリスト取得、DA取得、シートの整形 |
| 検索者になりきって目次構成を作る | 上位記事の見出し抽出、下調べ |
| 体験を書く | 文章の整形、誤字チェック |

## この手順書の育て方

- 1ステップずつ「検討中 → 確定」にしていく。一気に全部は書かない
- サイト固有の話が混ざりそうになったら、そのサイトのリポジトリに書く
- 実運用で手順どおりに動かなかった箇所は、その場でこのリポジトリを直す
- 新しいノウハウを読んだら、まず references/ に要約を置き、次に該当ステップへ反映する
