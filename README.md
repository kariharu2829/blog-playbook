# ブログ運営の型（汎用版）

どんなジャンル・どんな案件でも同じ手順で回すための運営手順書。
特定サイトの固有事情はここに書かない（各サイトのリポジトリに書く）。

## ブログは1本の数式を回す事業

```
月収益 = 検索流入数 × 記事→案件ページ遷移率 × 成約率 × 1件あたり報酬
```

すべての工程は、この4つのどれかを上げるためにある。
**左側（案件と単価）を先に決めてから、右側（記事）を作る。** この順番を崩すと後で全部書き直しになる。

状態は「未着手 → 検討中 → 確定」の3段階。確定したステップだけを実運用で使う。

### 第1層 設計：ここで収益の8割が決まる
1. **ゴール設定**：目標月収・期限・週の投下時間・外注予算から、必要記事数と必要単価を逆算する
2. **案件選定**：報酬単価・承認率・EPC・成果地点・競合強度・自分の体験資産で案件を先に決める
3. **市場・競合調査**：上位サイトの運営者属性・記事本数・ドメイン強度から、個人が勝てる隙間を判定する。撤退判断もここで行う
4. **ペルソナ設定**：読者ペルソナと発信者ペルソナの2つを作る
5. **キーワード設計**：収益KWを起点に、集客KW → 比較KW → 成約KWのクラスタを組み、記事一覧表を先に完成させる
6. **サイト設計**：コンセプト・カテゴリ・内部リンク導線・CVポイント・E-E-A-Tの担保要素を決める

### 第2層 制作：記事1本ごとに繰り返す
7. **記事設計**：上位記事の見出し分析、独自要素の決定、構成案の作成と承認
8. **執筆**：文体ルール、根拠と体験の入れ方、法令チェック（景表法・薬機法・ステマ規制）
9. **仕上げ・公開**：画像・CTA・内部リンク・メタ情報・公開前チェックリスト

### 第3層 運用：公開後に回し続ける
10. **計測**：GSC・GA4・ASP管理画面で見る指標と、見る頻度を固定する
11. **リライト・改善**：順位・CTR・CVRのどこが詰まっているかで打ち手を分ける
12. **拡張・仕組み化**：外注化、SNS・メルマガ、横展開サイト、案件の特単交渉

## 1ステップの型

各ステップは必ず同じ6項目で書く（雛形: [_template/ステップの型.md](_template/ステップの型.md)）。

- **目的**：このステップで何が決まれば次に進めるか
- **インプット**：前のステップから受け取るもの
- **やること**：手順を番号で
- **アウトプット**：成果物のファイル名と形式
- **完了基準**：数値か Yes/No で判定できる条件
- **よくある失敗**：典型的な脱線パターン

## この手順書の育て方

- 1ステップずつ「検討中 → 確定」にしていく。一気に全部は書かない
- サイト固有の話が混ざりそうになったら、そのサイトのリポジトリに書く
- 実運用で手順どおりに動かなかった箇所は、その場でこのリポジトリを直す
