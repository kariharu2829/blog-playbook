# ブログ運営の型（汎用版）

どんなジャンル・どんな案件でも同じ手順で回すための運営手順書。
特定サイトの固有事情はここに書かない（各サイトのリポジトリに書く）。

## ブログは1本の数式を回す事業

```
月収益 = 検索流入数 × 記事→案件ページ遷移率 × 成約率 × 1件あたり報酬
```

すべての工程は、この4つのどれかを上げるためにある。
**左側（案件と単価）を先に決めてから、右側（記事）を作る。** この順番を崩すと後で全部書き直しになる。

ブログは「営業代行」という事業。創業計画書の「取扱商品・客単価・売上」が埋まらないブログは、ゴールのないマラソンになる。
現役で稼いでいる3人のブロガーの流れは全員同じで、**売る商品を決める → その商品を売るKWを選ぶ → 上位を取れる構成を作る → 書いて出す → 分析して直す**。この骨格をそのまま採用する。

状態は「未着手 → 検討中 → 確定」の3段階。確定したステップだけを実運用で使う。

### 土台：ここで収益の9割が決まる（1か月かけてよい）
0. **ゴール設定**：目標月収・期限・投下時間・体験資産を棚卸しし、ラッコM&Aの実データで必要記事数と必要単価を逆算する
1. **売る商品を決める**：ASPを1週間かけて全件見て、成果報酬 ＞ 成果条件 ＞ EPC ＞ 確定率 の順で主力1件・サブ2件までを決める
2. **キーワード選定**：商品を売るKWを1週間かけて洗い出し、Google検索で「1ページ目に個人ブログがあるか」「DAは低いか」を自分の目で確かめ、グループ化して優先順位と記事一覧を作る。**ここが終わるまでブログを開設しない**

土台3ステップの成果物は **「ブログ創業計画書」1枚**に集約する（取扱商品と客単価／目標売上と必要PV・必要記事数／狙うKW一覧と導線／週あたり公開本数と12か月マイルストーン）。

### 記事ごと：1本ずつ繰り返す
3. **タイトル・目次構成**：本人が先に仮説を書き、AIのリサーチシートで答え合わせし、本人が確定する。3ルール＝重要なH2から順に／H3はH2の答え／余計なH2を書かない。AIに丸投げしない
4. **執筆・公開**：AIが初稿、本人がリード文・体験・セールスを書き、本文を直す。FAQは実際の質問から。公開前チェックを通し、本人が公開する。最後に差分学習でトンマナMDを育てる。完璧は求めない
5. **分析・改善**：公開4週間後に初めて順位を見る。毎月1日に全記事の順位・CTR・遷移・成約を一覧にし、分岐表で「詰まっている場所」を判定して月3〜5本をリライトする。10〜20位が本命。3か月ごとに案件と逆算の変数を見直す

### 超えてから
6. **拡張・仕組み化**：外注化、横展開サイト、案件の特単交渉、SNS・メルマガ。月5万円を超えるまで手を出さない

## 数値の目安（3人の実践者のばらつきを優先順位で吸収）

| 項目 | こーにゃん氏 | やましょ氏 | ぴーたん氏 | 手順書での扱い |
|---|---|---|---|---|
| 成果報酬の下限 | 3,000円、好ましくは5,000円 | 3,000円 | 2,000円 | 2,000円未満は見ない。3,000円以上を候補、5,000円以上を優先 |
| 承認率・確定率 | 60%、好ましくは80% | 50% | 記載なし | 50%未満は落とす。60%以上を候補、80%以上を優先 |
| 検索ボリューム | 100以上を優先 | 10以上 | 10〜100の3語KW | 10未満は書かない。10〜100を初期の主戦場、100以上を優先 |
| 個人ブログの存在 | 1ページ目に1つでもあれば狙う | 1ページ目に個人サイトがある | 記載なし | 必須条件 |
| DA | 20未満、好ましくは1桁 | 記載なし | 記載なし | 20未満を候補、10未満を優先 |

## 手順書は2階建て

- `steps/`：人が読む手順書。目的・インプット・やること・アウトプット・完了基準・よくある失敗
- `prompts/`：その手順のうちAIに任せる部分を、そのまま読ませるファイル（[prompts/README.md](prompts/README.md)）。記事ごとの層は毎回回すので、人が指示を打ち直さずに済むよう仕組み化する。トンマナMDのようにサイトごとに育つものは雛形だけ置き、実体は各サイトのリポジトリに持つ

## 1ステップの型

各ステップは必ず同じ6項目で書く（雛形: [_template/ステップの型.md](_template/ステップの型.md)）。

- **目的**：このステップで何が決まれば次に進めるか
- **インプット**：前のステップから受け取るもの
- **やること**：手順を番号で
- **アウトプット**：成果物のファイル名と形式
- **完了基準**：数値か Yes/No で判定できる条件
- **よくある失敗**：典型的な脱線パターン

## 役割分担の原則（全ステップ共通）

| 本人がやる（AIに任せない） | AIやツールに任せてよい |
|---|---|
| ASPの全件閲覧と、自分の経験との照らし合わせ | お気に入りの一覧化、評価表への転記、新着通知 |
| 検索結果を見て「1ページ目に入れるか」を判断する | KWリスト取得、DA取得、シートの整形 |
| 検索者になりきって目次構成を作る | 上位記事の見出し抽出、下調べ |
| 体験を書く | 文章の整形、誤字チェック |

## この手順書の育て方

- 1ステップずつ「検討中 → 確定」にしていく。一気に全部は書かない
- サイト固有の話が混ざりそうになったら、そのサイトのリポジトリに書く
- 実運用で手順どおりに動かなかった箇所は、その場でこのリポジトリを直す
- 新しいノウハウを読んだら、まず references/ に要約を置き、次に該当ステップへ反映する
