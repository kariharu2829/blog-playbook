# ステップ2：案件選定

状態: 確定　　最終更新: 2026-09-10

骨格は [references/案件選定_元記事メモ.md](../references/案件選定_元記事メモ.md) の6ステップと優先順位を採用し、ゴール設定との接続・体験資産・LP確認・提携申請・売る場所の判断を加えたもの。

## 目的
**売る商品（主力案件）を先に決める。** ブログを作ってから商品を探すのではなく、商品を見つけてからブログを作る。
主力案件が決まると、記事の導線の終点・ペルソナ・キーワードがすべてここから逆算できる。

## インプット
- `goal.md`（ステップ1）
  - 選んだ型 → 報酬の下限になる（高単価型=5,000円以上、中単価型=3,000〜5,000円）
  - 体験資産の棚卸し表 → 案件との照らし合わせに使う

## 役割分担
| 作業 | 誰が |
|---|---|
| ASPの全件閲覧と、自分の過去・現在・未来との照らし合わせ | **本人**。ここはAIに任せない |
| お気に入りの一覧化、評価表への転記、新着通知 | AIに任せてよい |
| KWの広がりの事前確認、LPの訴求点書き出し | AIに下調べさせ、本人が判断 |

## やること

### 1. ASPに登録し、1週間かけて全案件を見る
- 主軸は A8.net（案件数最大、ブログがなくてもSNSアカウントで登録可、EPC・確定率が載っている）
- 他ASP（もしも・バリューコマース・afb・アクセストレード）は主力候補が絞れてからサブで見る
- 見る前に、ステップ1の体験資産表を手元に置く。「現在の身の回り」→「過去にハマった物」→「将来欲しい物・ありたい姿」の順に照らし合わせる
- 気になった案件は「お気に入り」に入れる。一覧化はあとでよい

### 2. 4指標で見る（優先順位を守る）

```
成果報酬 ＞ 成果条件 ＞ EPC ＞ 確定率
```

| 指標 | 目安 | 見方 |
|---|---|---|
| 成果報酬 | ステップ1の型の下限以上。最低3,000円、好ましくは5,000円以上 | 成果報酬の高い順にソートして見る |
| 成果条件 | 購買ハードルが低い＝成果地点が近いもの | 報酬とシーソーの関係。報酬が下がりすぎない範囲で近いものを選ぶ |
| EPC | 70以上、好ましくは100以上 | 参考値。変動が大きく、半年で半分以下になることもある。盲信しない |
| 確定率 | 60%以上、好ましくは80%以上 | 成果地点が近いほど高くなりやすい。低いと報酬が目減りする |

4指標は単独で見ず、相互作用で見る。成果報酬と成果条件の2つで判断できるなら進めてよい。

### 3. 「ー」の案件は成果条件で解釈し、保留に置く
「ー」はデータ不足であって悪い案件の印ではない。「ー」だけを理由に外さない。

| 成果条件 | 「ー」の解釈 | 扱い |
|---|---|---|
| 資料請求・無料登録（成果地点が近い） | まだ知られていないだけの可能性 | 保留に置いて他と比べる |
| 購入・有料契約（成果地点が遠い） | 売りにくい可能性 | 優先順位を下げる |

### 4. 案件評価表に落とす
お気に入りを次の列で一覧化する（`offers.md` または表計算）。

| 列 | 内容 |
|---|---|
| 案件名 / ASP | |
| 成果報酬 | 円 |
| 成果条件 | 成果地点の近さ（無料登録・資料請求・購入・有料契約など） |
| EPC / 確定率 | 「ー」はそのまま「ー」と書く |
| 期待報酬 | 成果報酬 × 確定率（「ー」なら成果条件から仮置きし、仮と明記） |
| 体験資産との適合 | 「今書ける」「体験する計画を立てられる」「体験する気がない」の3分類 |
| NG表現・承認条件 | 広告主の掲載条件、禁止表現、審査の有無 |
| 判定 | 候補 / 保留 / 落選 |

「体験する気がない」だけは落とす。未体験でも、契約・購入・利用の計画を立てられるなら候補に残せる。

### 5. 主力候補のKWの広がりを軽く確かめる
ASPを見るだけでは案件選定は閉じない。主力候補について次を確認する（本格的なKW設計はステップ5）。
- 商標KW以外に関連KWが出てくるか
- 商標KWだけなら1〜2記事で終わる規模。関連KWが次々出るならブログが1つ成り立つ規模
- 関連KWが出ない案件は、主力ではなくサブか保留に回す

### 6. 売る場所を決める（既存ブログがある人向け）
これから始める人は新ドメイン一択。既存ブログがある人は2軸で決める。

| | 既存ブログと関連あり | 関連なし |
|---|---|---|
| KWが広がる | どちらもあり。既存に足して育ててから切り出す手も | 新ドメインで特化 |
| KWが少ない | 既存ブログに1本書いてみる | 保留。お気に入りのまま寝かせる |

「いま動かない」も判断のひとつ。書く場所もKWもない状態で始めると、記事が増えずドメインも育たない。

### 7. 主力1件・サブ2件まで に絞る
- 1商品または1商品群に特化する。「〇〇といえばこのブログ」を狙う。特化はE-E-A-Tを高める
- 主力1件＝記事導線の終点になる案件。サブは同じ商品群の中で2件まで
- 10件並べて「全部書く」は導線が散る。絞る

### 8. 主力案件のLPを見て、訴求点と成約導線を書き出す
- 広告主のLPで「何を一番に訴求しているか」「成約までに何画面あるか」「成果条件の地点はどこか」を書き出す
- 記事のCTAで勧める行動と成果条件を一致させるため。ここを飛ばすと、成果条件は有料契約なのに記事は無料登録を勧める、というズレが起きる

### 9. 主力案件の提携申請を出す
- 候補が確定した時点で申請する。記事ができてから審査に落ちるのを防ぐ
- 審査落ちしたら、サブを繰り上げるか、評価表に戻って選び直す

### ルーティン：新着プログラムを見る
- 新着順に並び替え、カテゴリを問わず見る。市場調査＝トレンド把握であり、ライバルが少なく先行者利益を狙える
- 頻度は週1回以上。通知はAIエージェントに任せてよい
- 良い案件を見つけたら「6. 売る場所を決める」の4象限で判断する

## よくある失敗
- **報酬だけ見て成果地点が遠い案件を主力にする**：確定率が低く、記事のCTAも弱くなる。成果条件とセットで見る
- **EPCを絶対条件にする**：「ー」や低EPCで有望案件を落とす。EPCは参考値、優先順位に戻る
- **成果条件と記事のCTAがずれる**：有料契約が条件なのに無料登録を勧める。LP確認で防ぐ
- **10件以上を「全部書く」と決める**：導線が散り、どの案件も中途半端になる。主力1件に絞る
- **商標KWしかない案件で新ドメインを立てる**：1〜2記事で書くことがなくなりドメインが育たない。KWの広がりを先に見る
- **提携申請を後回しにする**：記事完成後に審査落ち。候補確定の時点で申請する
- **ASPの閲覧をAIに丸投げする**：「稼げる商品は？」の答えは全員に同じ。自分の経験と案件を照らす作業は本人がやる
- **使う気も体験する気もない案件を選ぶ**：体験が書けず、企業サイトの劣化コピーになる
