# ステップ3：タイトル・目次構成

状態: 確定　　最終更新: 2026-09-11

骨格は [references/5ステップ_やましょ氏メモ.md](../references/5ステップ_やましょ氏メモ.md) の❸（目次構成の3ポイント、自分の頭で作る）と [references/AI記事制作フロー_元記事メモ.md](../references/AI記事制作フロー_元記事メモ.md) のリサーチシート（AIが判断材料を作り、人が9割組む）。「本人が仮説 → AIで答え合わせ → 本人が確定」の順にして両立させた。

## 目的
**そのKWで検索する読者が一番知りたいことに、最短で答える構成を確定する。**
構成の質で上位が取れるかが決まる。本文はここが終わるまで書かない。

## インプット
- KWシートと記事一覧（ステップ2）：今日書く記事の代表KW、グループ内KW、役割（成約／集客／橋渡し）、流す先
- ブログ創業計画書：主力商品、成果条件、LPの訴求点
- ライバルの収益源記事のメモ（ステップ2の6.）
- `prompts/記事構成リサーチ.md`

## やること

### 1. 今日書く記事を1本選ぶ
- 記事一覧の優先順位どおりに選ぶ。最初は成約記事から
- 代表KW・グループ内KW・役割・流す先を確認する

### 2. 本人が仮説を書く（10分。AIより先に）
検索窓にそのKWを打つ人になりきって、メモ書きする。
- この人は何を一番知りたいか（1つ）
- 前提知識はどこまであるか（商品名を知っているか、比較中か、購入直前か）
- 読み終えたらどうなっていたいか
- 自分ならどんな見出しが並んでいたら読み進めるか（H2を3〜6個、思いつくまま）
- 主力商品をどこで、どういう理由で勧めるか

先に自分で考える理由は2つ。AIや上位記事を先に見ると「真似と足し算」しかできなくなること。仮説と答え合わせをすると自分の読みが鍛えられること。

### 3. AIにリサーチシートを作らせる
- `prompts/記事構成リサーチ.md` を読ませ、仮説メモと記事の役割を渡して「〇〇で記事構成を作って」
- 出てくるもの：検索意図の深掘り、KW4種（実データ）、上位10記事のタイトルと見出し、共通トピック／足りないトピック／不要な見出し、タイトル10案、H2/H3構成案、仮説との差分
- 本文は書かせない

### 4. 仮説とシートを突き合わせる
- 共通トピック（5サイト以上が扱う）が仮説から漏れていないか。漏れは必須要素として足す
- 足りないトピック（上位が書いていない）のうち、自分の体験・実測・独自データで埋められるものを1つ以上入れる。ここが差別化
- 不要な見出しがシートの構成案に紛れていないか。「〇〇とは」「歴史」「基本情報」は検索意図に合わなければ削る
- 上位記事が企業ドメインやDAだけで上位の場合、構成の質は参考にしない

### 5. 構成を確定する（3ルール）
1. **最も見てほしい重要なH2から順に置く**。読者は全部読まない。最初のH2が読者の一番知りたい答え（結論・比較表・体験の要約）。なぜこのH2が一番上か、1行で説明できること
2. **H3はH2の答えを書く**。H2「口コミ3選」ならH3は3つの口コミ。目次だけ読んで記事の内容が分かる状態にする。H3は疑問形より言い切り
3. **余計なH2を書かない**。検索者の前提知識に合わせ、知っていることを説明しない。足し算で詰め込まない

あわせて構成に印を付ける。
- 【体験】実体験を入れる位置（1記事に3か所以上）
- 【CTA】主力商品を勧める位置。成約記事は導入後・メリット後・料金後・まとめの4か所、集客記事は「悩み → わが家の解決策 → でも〇〇ならもっと楽 → リンク」の流れで1〜2か所
- 【リード】【セールス】は本人が書く部分として印を残す
- FAQのH2を終盤に置く（中身はステップ4で作る）
- 内部リンクで流す先（記事一覧の「流す先」）を該当H2の横にメモする

### 6. タイトルを決める
- 10案から本人が選ぶ。基準はメインKWが左寄せ、30字前後（32字以内）、読者が一番知りたいことが伝わる、競合と同じ切り口にしない
- 誇大表現は使わない

### 7. 「本文GO」を出す
- 確定した構成（印つき）とタイトルを記事フォルダの `structure.md` に保存する
- ここで初めてステップ4に進む

## アウトプット
- 記事フォルダの `structure.md`
  - 代表KW・グループ内KW・役割・流す先
  - 本人の仮説メモ
  - 確定した構成（H2/H3、【体験】【CTA】【リード】【セールス】の印、内部リンク先）
  - 確定タイトルと、選ばなかった案の理由（1行）
  - リサーチシートへのリンク

## 完了基準
- [ ] AIを動かす前に、本人の仮説メモが書いてある
- [ ] 目次だけ読んで記事の内容が分かる
- [ ] 最初のH2が、読者の一番知りたい答えになっている。なぜ一番上かを1行で説明できる
- [ ] すべてのH3が、親のH2の答えになっている
- [ ] 検索意図に不要なH2（〇〇とは・歴史・基本情報など）がない
- [ ] 上位が書いていないトピックのうち、自分の体験や独自データで埋めるものが1つ以上入っている
- [ ] 【体験】が3か所以上、【CTA】が役割に応じた数だけ印されている
- [ ] 【リード】【セールス】が本人担当として印されている
- [ ] タイトルが32字以内でメインKWを含み、誇大表現がない
- [ ] `structure.md` に保存し、「本文GO」を出している

## よくある失敗
- **構成をAIに丸投げする**：上位記事の真似と足し算になり、読者が一番知りたいことが埋もれる。AI案は判断材料
- **仮説を書かずにシートから始める**：自分の読みが鍛えられず、毎回AI頼みになる
- **上位記事の見出しを全部入れる**：詰め込んでも良い記事にならない。共通トピック＋差別化1つで足りる
- **H2の答えがH3にない**：「まずは失敗談」「注意点」のようなH3を「5ステップ」のH2の下に置く。目次で内容が分からなくなる
- **「〇〇とは」から始める**：「体験談」で検索した人は体験談をすぐ見たい。前提知識を考える
- **構成確認を飛ばして本文まで書かせる**：直すのが大変な長文が出てくる。「本文GO」を必ず挟む
- **【体験】の位置を決めない**：本文でAIがそれらしい文で埋め、創作体験になる。位置を先に決めて印を残す
