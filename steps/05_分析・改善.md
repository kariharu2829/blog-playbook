# ステップ5：分析・改善

状態: 確定　　最終更新: 2026-09-11

骨格は [references/5ステップ_やましょ氏メモ.md](../references/5ステップ_やましょ氏メモ.md) の❺（サーチコンソールで狙ったKWの順位を見る。10〜20位ならリライトで1位へ）。頻度・指標・打ち手の分岐は経験則で補ったもの。実運用で合わなければ直す。

## 目的
**公開した記事が狙ったKWで上位に入っているかを数字で確認し、詰まっている場所に合わせた打ち手でリライトする。**
公開はゴールではなく計測の開始点。いきなり1位は稀で、10〜20位に入っていればそこから1位を取りに行く。

## インプット
- 記事ログ（ステップ4）：公開日、代表KW、URL、【Level2予定】
- Search Console（GSC）、GA4、ASP管理画面
- KWシート（ステップ2）：狙ったKWと、当時の上位10のDA
- 記事フォルダの `structure.md` `ready.md`

## 役割分担
| 作業 | 誰が |
|---|---|
| GSC・GA4・ASPから数字を取り、記事一覧に転記する | AI（API連携があれば）／なければ本人がCSVを貼る |
| 「詰まっている場所」の判定と、打ち手の決定 | **本人**。AIは分岐表に沿った下案まで |
| リライト本文の初稿 | AI（ステップ4と同じ分担） |
| 体験の追記 | **本人** |

## やること

### 1. 見る頻度を固定する
| タイミング | 見ること |
|---|---|
| 公開当日 | GSCのURL検査でインデックス登録をリクエスト |
| 公開1〜2週間後 | 【Level2予定】の体験追記（実測データ・使用感） |
| 公開4週間後 | GSCで初めて順位を見る。狙ったKWで表示されているか、何位か |
| 毎月1日 | 全記事を一覧で見て、詰まっている場所と次の打ち手を決める |
| 公開3か月後 | 順位が安定したとみなし、本格リライトの対象に入れる |

順位がつくまで数週間〜数か月かかる。**公開4週間以内に順位で一喜一憂しない。**

### 2. 記事一覧に数字を入れる（毎月1日）
列は次のとおり。

| 列 | 出どころ |
|---|---|
| 記事No / 代表KW / URL / 公開日 | 記事ログ |
| 順位（狙ったKW） | GSC 検索パフォーマンス（クエリ別） |
| 表示回数 / クリック数 / CTR | GSC |
| 実際に流入しているKW上位3つ | GSC（狙ったKWと違うことがある） |
| 案件ページへのクリック数 | GA4イベント or ASPのクリック数 |
| 発生件数 / 確定件数 / 確定報酬 | ASP管理画面 |
| 詰まっている場所 | 本人が3.で判定 |
| 次の打ち手 / 期限 | 本人が決める |
| 最終リライト日 / 変更点 | 記録 |

### 3. 詰まっている場所を判定する（分岐表）
上から順に見て、最初に当てはまった場所が打ち手。

| 症状 | 詰まっている場所 | 打ち手 |
|---|---|---|
| 表示回数がほぼ0 | インデックス未登録、またはKWと内容のずれ | URL検査で登録状況を確認。登録済みならタイトル・H2に代表KWが入っているか、検索意図と構成が合っているか見直す |
| 表示はあるが順位が21位以下 | 構成・内容が上位に届いていない | 上位10記事を再確認し、共通トピックの漏れと差別化要素の不足を埋める。DAが高いサイトばかりなら言い換えKWへの転換も検討 |
| 順位10〜20位 | **リライトの本命** | 構成の見直し（最初のH2は一番知りたい答えか）、体験・独自データの追加、情報の鮮度更新。ここから1位を狙う |
| 順位1〜9位だがCTRが低い（目安3%未満） | タイトル・メタディスクリプション | 実際に流入しているKWに合わせてタイトルを直す。数字・具体語を入れる |
| 流入はあるが案件ページへの遷移がない | CTAの位置と文言 | CTAを「読者が判断し終えた直後」に移す。ボタン文言を成果条件に合わせる |
| 遷移はあるが成約しない | 成果条件とのずれ、LPとの訴求不一致、案件そのもの | 記事で勧めた行動と成果条件を照合。LPの訴求点と記事の訴求点を合わせる。それでも0ならサブ案件に切り替える |
| 狙ったKWと違うKWで流入している | 検索意図の読み違い | 流入しているKWが商品に近ければ、そのKWに構成を寄せる。遠ければ別記事に切り出す |

### 4. リライトの優先順位を決める
1. 順位10〜20位で、検索ボリュームがあり、主力商品に近い記事
2. 順位1〜9位でCTRが低い記事（タイトル修正だけで効く）
3. 遷移・成約が詰まっている成約記事（CTA修正）
4. 21位以下の記事は、上の3つが終わってから

- 月に直すのは3〜5本まで。全部触ると効果が測れない
- **公開3か月以内の記事は、体験追記とタイトル修正以外は触らない**。順位が安定していないうちの構成変更は測れない

### 5. リライトする
- ステップ3・4と同じ流れで行う。構成の見直しは本人、初稿はAI、体験は本人
- 変えた箇所と理由を記事ログに書く。効いたかどうかを翌月・翌々月に見る
- 公開日は更新日に書き換える（内容が実質的に変わった場合のみ）

### 6. 体験を追記する（Level2）
- 公開時に【Level2予定】を置いた記事は、1〜2週間後に実測データや使用感を追記する
- 追記は本人。AIに補完させない
- 追記したら印を消し、記事ログに追記日を書く

### 7. 案件と全体を見直す（3か月ごと）
- 発生・確定を案件別に集計し、確定率がステップ1の目安（60%）を下回り続ける案件はサブへ降格を検討する
- 記事一覧全体で「成約記事に流入が集まっているか」「集客記事から成約記事へ流れているか」を見る。流れていなければ内部リンクの位置を直す
- ステップ0の逆算（必要PV・必要記事数）を実測で差し替える。ここが「仮置き値の差し替え」の実行タイミング

## アウトプット
- 記事一覧（サイトのリポジトリ。2.の列。毎月更新）
- 記事ログの更新：詰まっている場所、次の打ち手、リライト日と変更点、Level2追記日
- ブログ創業計画書の更新（3か月ごと）：逆算の変数を実測に差し替え

## よくある失敗
- **公開直後に順位を見て落ち込む、または触る**：順位がつくまで数週間〜数か月。4週間は見ない
- **全記事を毎月いじる**：どの変更が効いたか分からなくなる。月3〜5本
- **順位だけ見て、遷移と成約を見ない**：1位でも売れなければ意味がない。ASPの数字まで一覧に入れる
- **タイトルを変えれば済む記事の構成を全部直す**：分岐表を上から順に見る。軽い打ち手から
- **リライトで体験をAIに補完させる**：ステップ4と同じ。体験は本人だけ
- **仮置き値を差し替えない**：3か月ごとの見直しで、ステップ0の数字を実測にする
- **成約しない案件を主力のまま放置する**：確定率が目安を下回り続けるならサブへ。案件の見直しは失敗ではなく手順
