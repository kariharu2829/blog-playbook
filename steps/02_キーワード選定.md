# ステップ2：キーワード選定

状態: 確定　　最終更新: 2026-09-11

骨格は [references/キーワード選定_元記事メモ.md](../references/キーワード選定_元記事メモ.md)（こーにゃん氏）の9ステップ。[references/5ステップ_やましょ氏メモ.md](../references/5ステップ_やましょ氏メモ.md) の「商品が解決策になるKW」と、[references/創業計画書_ぴーたん氏メモ.md](../references/創業計画書_ぴーたん氏メモ.md) のお悩みKW抽出・獲得キーワード調査を統合し、役割ラベル・記事一覧・ゴール設定との突き合わせを加えたもの。

## 目的
**主力商品を売るためのKWを洗い出し、自分の目で「1ページ目に入れるか」を確かめ、書く順番まで決める。**
売る商品とKWの2つを間違えると、何百記事書いても稼げない。ここに1週間かける。**ここが終わるまでブログを開設しない。**

用語: **キーワード選定**＝どのKWで書くかを決める一連の流れ。**キーワード調査**＝その中で検索ボリューム・CPC・ライバルの強さを調べる工程。

## インプット
- ブログ創業計画書（ステップ0・1で埋めた欄）
  - 主力1件・サブ2件の案件名、成果条件、LPの訴求点
  - 必要記事数（ステップ0の逆算）
  - M&A実データ表の「収益源」欄（同ジャンルの稼いでいるサイトのURLがあれば競合調査に使う）

## 役割分担
| 作業 | 誰が |
|---|---|
| 検索結果を見て「個人ブログが1ページ目にいるか」「勝てるか」を判断する | **本人**。ここはAIに任せない |
| KWリスト取得、CSV整形、DA転記、シートの色分け、グループ化の下案 | AIやツールに任せてよい |
| 上位記事の見出し抽出、獲得キーワード調査の結果整理 | AIに下調べさせ、本人が判断 |

## やること

### 1. 商標KWから関連KWリストを取得する
- ツールは GetKeyword（無料・SMS認証で月40回）、ラッコキーワード（月間検索数は有料。まずエントリー1か月）、Ubersuggest のいずれか。数値はツールで違うので目安として使う
- 主力案件の商標名を入れ、サジェストをCSVでダウンロードしてスプレッドシートに入れる
- **この時点で絞らない。丸ごと取る**。取れるのはKW・検索ボリューム・CPC・競合性
- サブ案件の商標、ジャンル名（例: 宅食）でも同じことをする

### 2. 「商品が解決策になる」お悩みKWを足す
商標KW（「〇〇 口コミ」「〇〇 比較」）は登録一歩手前の人が検索するので売りやすいが、企業サイトが並び個人では勝ちにくい。だから**売り物が解決策になり、競合が弱いKW**を足す。
- 主力商品を使う人が抱えている悩みを、自分の経験から10個以上書き出す（例: 「夏までに5キロ痩せたい」「共働き 夕食 どうしてる」）
- Google検索の「他の人はこちらも検索」「関連する質問」からお悩みKWを拾い、それをまたサジェスト取得にかける
- SNSの検索窓も需要の目安にする（Instagramは投稿件数、X・Threadsは量と新しさ）
- お悩みKWは集客ワードとしてサイトに入れる。悩みに答えるので他者貢献であり、ニーズがある

### 3. 1KWずつ、シークレットモードでGoogle検索する
ログイン状態や履歴で検索結果は変わる。自分がよく見るサイトを「強い」と誤判定しないよう、必ずシークレットモードで見る。
1KWごとに次の3つを見る。

**①検索意図（バーティカル検索の一番左のタブ）**
「AIモード」「すべて」を除いて一番左にあるタブで、読者が何をしたいかを推測する。

| 一番左のタブ | クエリ | 扱い |
|---|---|---|
| ショッピング | Buy（買いたい） | 成約に近い。優先。ただし激戦 |
| 動画・ショート動画 | Do（やりたい） | 成約に近い。優先 |
| 地図・フライト・旅行 | Go（行きたい） | 成約に近い。優先 |
| ニュース・書籍 | Know（知りたい） | 集客向け |
| 画像 | 検索結果で判断 | |

**②個人ブログの存在（上位10記事）**
- ドメインで目星をつける。`.co.jp` `.ac.jp` `.go.jp` は企業・学校・官公庁。`.com` `.net` `.jp` は個人の可能性
- 企業も `.com` を使うので、タイトルをクリックして運営者情報で確認する
- **1ページ目に個人ブログが1つでもあれば狙う価値あり**
- 1つもなければ、言い換えKWで再検索する（日本語⇔英語・略語、漢字⇔かな⇔カタカナ、正式名称⇔通称、専門用語⇔日常語）。意味が同じでもGoogleは別KWとして扱い、顔ぶれが変わる

**③ライバルの強さ（DA）**
- Chrome拡張の Ubersuggest で、検索結果に各サイトの DA（Moz ドメインオーソリティ、1〜100）が出る。無料は1日40回
- **DA20未満、好ましくは1桁の個人ブログが1ページ目にいれば、個人でも上位表示の可能性が高い**
- DA1桁で上位にいる記事には理由がある。中身を見て、タイトル・見出し・独自要素をメモする（ステップ3で使う）
- DAは日で多少上下するが、1〜2の差で判断は変わらない。数か月前の数値は当てにならないので取得日を残す

### 4. 上位表示できたら商品が売れるか、を1KWごとに問う
上位表示できたのに商品と無関係で1円も稼げない、が最も痛い失敗。KWごとに「このKWで来た読者に、主力商品を解決策として自然に勧められるか」を Yes/No で書く。No のKWは、集客記事として他記事へ流す設計にできない限り落とす。

### 5. スプレッドシートにまとめる
列は次のとおり。

| 列 | 内容 |
|---|---|
| KW | |
| 検索vol | ツールの値。目安 |
| CPC | 高いほど収益性が高い |
| 競合性 | ツールの値 |
| 1位DA〜10位DA | 10列 |
| DA平均 | |
| 個人ブログの有無 | 1ページ目に何サイト |
| バーティカル検索 | 一番左のタブ |
| クエリ判定 | Buy / Do / Go / Know |
| 商品が解決策になるか | Yes / No |
| 役割 | 成約KW（商標・比較・料金・口コミ）／ 集客KW（悩み・やり方）／ 橋渡しKW（集客から成約へつなぐ） |
| 取得日 | |

DA列は条件付き書式で色分けする。ルールは「10未満」を上、「20未満」を下に置く（上のルールが優先されるため）。

```
ルール1: =AND(E2<>"", E2<10)
ルール2: =AND(E2<>"", E2<20)
```

### 6. 獲得キーワード調査でライバルの収益源を特定する
検索で何度も目にする個人ブログ、M&A実データ表にあった同ジャンルのサイトについて、ラッコキーワードの「獲得キーワード調査」にURLを入れる。
- そのサイトが「どのKWで・何位で・どれだけ流入しているか」が出る＝収益構造そのもの
- 流入の柱になっている記事（多くは「商品名 口コミ」「ジャンル 比較」）を**収益源の記事**として控える
- 上位KWが重複する競合サイト（ライバルのライバル）も拾い、同じことをする
- 見つけたKWで自分のシートにないものは追加する
- 収益源の記事は読み込み、構成と内容をメモする。自分が書くときは実体験と独自の分析で超える

### 7. 似たKWをグループ化する
- 検索意図が同じKW（「〇〇 口コミ」「〇〇 評判」「〇〇 レビュー」など）は1記事にまとめる。1グループ＝1記事
- 目的はカニバリ（自分の記事同士が同じKWで争い、どちらも順位が伸びない状態）を防ぐこと
- グループごとに代表KWを1つ決める

### 8. 優先順位を決め、記事一覧を作る
優先順位の目安。基準はあくまで目安で、読者の悩み解決に必要なら基準外でも書く。カニバリさえ避ければ書かなくていいKWはない。

| 条件 | 優先 | 候補 | 書かない |
|---|---|---|---|
| 検索ボリューム | 100以上 | 10〜100（初期の主戦場。ライバルも少ない） | 10未満 |
| 個人ブログ | DA10未満が1ページ目にいる | DA20未満が1ページ目にいる | 個人ブログなし（言い換えで再挑戦） |
| 収益性 | 成約KW、CPCが高い、Know以外 | 集客KW | 商品が解決策にならない |

記事一覧は次の列で作る。**成約KWから先に書く**。集客記事は成約記事へ内部リンクで流す前提で並べる。

| 記事No | 代表KW | グループ内KW | 役割 | 想定記事タイプ（体験記・比較・ランキング・使い方・悩み解決） | 流す先の記事No | 優先順位 |
|---|---|---|---|---|---|---|

### 9. ステップ0の必要記事数と突き合わせる
- 「優先」「候補」の記事本数が、ステップ0で逆算した必要記事数に届いているか
- 届かないなら、お悩みKWをさらに広げる → それでも足りなければサブ案件のKWを足す → それでも足りなければステップ1に戻って案件を見直す
- 届いていれば、**ここで初めてブログを開設してよい**

## 完了基準
- [ ] 主力商品の商標KWと、お悩みKWの両方からリストを取得している
- [ ] リストの全KWをシークレットモードで検索し、個人ブログの有無・DA・クエリ判定・取得日をシートに記録している
- [ ] 全KWに「商品が解決策になるか」の Yes/No がついている
- [ ] 同ジャンルのサイトを2つ以上、獲得キーワード調査にかけ、収益源の記事を控えている
- [ ] KWがグループ化され、1グループ1記事で記事一覧になっている
- [ ] 記事一覧に役割（成約・集客・橋渡し）と流す先が書いてある
- [ ] 「優先」「候補」の合計が、ステップ0の必要記事数に届いている（届かなければ対処を書いてある）
- [ ] 最初に書く成約記事が決まっている

## よくある失敗
- **KW選定をせず書きたいテーマで書く**：上位表示されず読まれない。実践者3人とも最初の2年をこれで失っている
- **商標KWだけで戦う**：企業が並ぶ激戦地。お悩みKWまで広げ、商品を解決策として置く
- **上位表示できても商品が売れないKWを書く**：Yes/Noの列を必ず埋める
- **ログイン状態で検索する**：自分がよく見るサイトを強いと誤判定する。シークレットモードで
- **検索ボリュームが小さいKWを捨てる**：10〜100はライバルも少ない初期の主戦場
- **DAだけで決める**：DA1桁で上位にいる記事には理由がある。中身を見る
- **グループ化せずに書く**：カニバリで自分の記事同士が潰し合う
- **KWが決まる前にブログを開設する**：開設すると「何か書きたく」なり、KW選定が雑になる
- **1ページ目に入れるかの判断までAIに任せる**：判断は自分の目。AIはリスト取得と整形まで
